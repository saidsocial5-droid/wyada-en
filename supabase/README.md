# Supabase backend

- `migrations/` — schema (33 tables, RLS) and the M1 lesson loop (`start_course`, `complete_lesson`).
- `seed.sql` — course content, generated by `node content/build-seed.mjs` from `content/*/course.json`. Never edit it by hand.
- `tests/run-local.sh` — runs migrations + seed + `tests/m1_test.sql` on a throwaway local Postgres 16. 15 checks: locking, unfinished/too-fast lessons, XP, idempotent replays, practice mode, streak across days and gaps, RLS.

## Connect a real project (once)

1. Create a project at supabase.com (EU region).
2. **Authentication → Sign In / Providers → allow anonymous sign-ins** (guests play first and sign up later).
3. SQL Editor: run `migrations/20261107000001_schema.sql`, then `migrations/20261107000002_m1_lesson_loop.sql`, then `seed.sql`.
   With the Supabase CLI instead: `supabase link --project-ref <ref>` then `supabase db push` and run `seed.sql`.
   If `create extension pg_cron` fails, enable pg_cron under Database → Extensions and run the file again.
4. Copy `app/.env.example` to `app/.env` and fill in the project URL and the **anon** key. Never put the service-role key in the app.
